# Contributing to Awlchemy

Thanks for helping fellow beginners. Small fixes are as welcome as features.

## Development setup

```
uv sync                 # creates .venv with the app + dev dependencies
uv run pytest           # offline tests: no network, no Claude Code, no real patterns needed
uv run awlchemy         # run the app against ./library and ./data
```

To try the UI with fake data and a fake teacher:

```
# PowerShell: $env:AWLCHEMY_HOME = "$env:TEMP\awlchemy-demo"
export AWLCHEMY_HOME=/tmp/awlchemy-demo
uv run python tests/make_fixtures.py "$AWLCHEMY_HOME"
uv run python tests/serve_fake.py      # http://127.0.0.1:8765, Claude Code replaced by tests/fake_claude.py
```

The public demo site is the same frontend with `demo/demo.js` in place of the server. If you change an API endpoint or what it returns, update `demo/demo.js` as well; `uv run pytest` tells you when the two drift apart (that test needs Node.js).

`CLAUDE.md` describes the architecture. Read it before larger changes.

## Ground rules

- **No pattern content or private links in the repo, issues or PRs.** That means:
  - no PDFs or screenshots of paid patterns
  - no text copied from them
  - no links to anyone's shared pattern folders
  
  Test fixtures are generated by `tests/make_fixtures.py` from text written for this project.
- **No secrets.** Settings live in `data/settings.json`, which is git-ignored. Don't add defaults that point at real folders or accounts.
- **Content you add must be yours or openly licensed**, compatible with AGPL-3.0. That covers knowledge files in `awlchemy/knowledge/`, images and prompts. Say where it comes from in the PR.
- Keep the AI sessions locked down. If you add a Claude Code feature, extend `claude_code.options()` with only the tools it needs, and cover it in `tests/fake_claude.py`.
- The UI is plain HTML/CSS/JS in `awlchemy/static/`, with no build step. Please keep it that way.

## Pull requests

1. Fork the repo, then create a branch from `main`.
2. Add or update tests and run `uv run pytest`.
3. Describe what changed and why. Include screenshots for UI changes (use sample data, not real patterns).

By contributing you agree your work is licensed under the AGPL-3.0-or-later, like the rest of the project.
